# 显影（Latent）

> macOS 上的 TMDB 元数据浏览器：搜索电影、剧集与人物，浏览趋势与筛选发现，收藏并管理自己的观看清单。纯 Swift + SwiftUI，零第三方依赖。
> 「显影」取意暗房工艺：影像在显影液里从无到有、缓缓浮现——这个应用让作品背后的信息同样浮现。英文名「Latent」指潜影（latent image）：信息一直都在，只待显现。
> 本文是 v1 规划，不是最终 API 设计。

## 结论

技术路线定为：

**SwiftUI（Observation 状态管理）+ URLSession/Codable 直连 TMDB（v4 Read Access Token 认证）+ 自研两级图片管线 + SwiftData（纯本地）。0 第三方依赖，无后端、无自有账号、无遥测。**

- 数据层：`TMDBClient`（actor）统一负责认证、请求节流、重试与错误分类；响应缓存与图片缓存独立于业务逻辑，可一键清除。
- 图片管线是自研重点：内存 NSCache + 磁盘 LRU + ImageIO 下采样 + 并发去重与取消，替代 Kingfisher/Nuke 的常用能力。
- 持久化采用 SwiftData（本地容器，不启用 CloudKit）：收藏、观看清单、历史全部 `@Model` 化；从 V1 起版本化 Schema + MigrationPlan。图片与响应缓存仍是文件缓存（缓存不入库）。最低系统 macOS 27，直接使用最新 SwiftData / SwiftUI API，不写兼容分支。
- 界面为两栏 `NavigationSplitView`（侧边栏 + 内容区，详情 Push 进入）；**海报是界面上唯一的大色块**，UI 只保留一个强调色；科技感来自精度、留白与秩序，而不是霓虹、玻璃与粒子。

## 1. 目标与非目标

### 目标

- 搜索 TMDB 的电影、剧集、人物，快速查看完整元数据（简介、评分、类型、演职员、剧照、相似推荐；剧集含季与分集）。
- 浏览趋势（今日 / 本周），并按条件筛选发现（类型、年份、评分、排序）。
- 收藏与观看清单：本地保存、随时回看（数据仅存本机）；右键复制 TMDB ID，直接配合蝉蜕的元数据确认流程使用。
- 与苹果生态耦合（纯本地能力）：SwiftData 数据层、系统分享（ShareLink）；v1.1 已接入 App Intents / Shortcuts / Spotlight 与 JSON / Markdown 导出。
- 中英双语元数据（默认 zh-CN，可切 en-US）；支持深 / 浅双主题，默认跟随系统。
- 纯 Swift + SwiftUI；无第三方依赖；无遥测；所有请求直连 TMDB。
- 界面极简：暗色优先、单一强调色、布局顺手、信息渐进披露、动效克制。

### 非目标（v1 不做）

- 播放任何内容：正片与预告片一律不在应用内播放——应用定位为纯元数据只读。
- 自建账号、云同步与跨设备同步（无付费开发者账号，数据仅存本机）。
- 社交功能（评论、动态、分享）。
- 把本地视频文件与 TMDB 自动匹配（那是蝉蜕的职责；本应用只做查询、复制与（v1.1）导出）。
- 自建代理后端；不做内置公共 Key（违反 TMDB 条款且不可控）。
- iOS / iPadOS 版；如将来做，Core 层不依赖 UI，可直接复用。

## 2. 硬性约束

- **语言**：业务与 UI 全部 Swift + SwiftUI；AppKit 仅用于 SwiftUI 覆盖不到的最小系统集成（预期不需要）。
- **系统框架**：SwiftUI、Observation、URLSession、Security（Keychain）、ImageIO、os.Logger、UniformTypeIdentifiers、SwiftData；v1.1 导出用 FileExporter，系统集成用 App Intents + CoreSpotlight（`IndexedEntity`）。
- **第三方依赖**：0。
- **网络**：仅 api.themoviedb.org 与 image.tmdb.org；App Sandbox 需要 `com.apple.security.network.client`。
- **凭据**：TMDB Read Access Token 存 Keychain（仅本机，不做 iCloud 钥匙串同步）；不写日志、不硬编码、不进数据库。
- **生态集成**：纯本地——SwiftData 本机容器、Keychain 本机条目；v1.1 接入 App Intents / Spotlight（纯本地能力，不需要付费开发者账号，但**需要可验证 Team ID**：免费 Apple Development 个人团队即可；ad-hoc 签名会被 linkd 拒绝）。
- **TMDB 合规**：关于页固定展示 "This product uses the TMDB API but is not endorsed or certified by TMDB."；应用名与图标不使用 TMDB 商标；请求频率与缓存策略遵守 TMDB 条款；提供一键清除缓存。
- **最低系统**：macOS 27.0（与开发机一致；不写任何向下兼容分支，直接使用最新 SwiftUI / SwiftData API 与系统外观）。开发环境：Xcode 27.1 / Swift 6.4 / macOS 27.0.1 / Apple M1 Pro。
- **并发**：Swift 6 严格并发；`TMDBClient` 与 `ImagePipeline` 为 actor；UI 状态 `@MainActor`；DTO 全 `Sendable`。
- **分发**：自用定位（Xcode 本地构建运行 / 自签名打包）；无付费开发者账号，不做公证与上架。App Sandbox + Hardened Runtime 仍照常配置（不影响本地运行，也为将来补账号留路径）。

## 4. TMDB API 设计

### 认证与验证

- 使用 **v4 Read Access Token**（Bearer 头），不用 v3 api_key 查询参数（Token 不进 URL、不进日志）。
- 设置页保存后立即调 `GET /3/configuration` 验证；401 提示 Token 无效；通过后缓存图片配置（base_url + sizes）。
- Token 存 Keychain：`service = app.latent.tmdb`，`account = read_token`（仅本机）。
  - **必须走传统（登录）钥匙串路径**：不使用 `kSecUseDataProtectionKeychain`——数据保护钥匙串要求签名带 `keychain-access-groups` / `application-identifier`（即需要 Team）。历史开发期使用 ad-hoc 签名时该路径直接返回 `errSecMissingEntitlement (-34018)`（已在「App Sandbox + ad-hoc」测试宿主中复现）；v1.1 为 App Intents 改用免费 Apple Development 个人团队签名后，仍保留传统登录钥匙串以兼容既有条目与测试。
  - **不得添加 `keychain-access-groups` entitlement**：ad-hoc 签名携带该受限 entitlement 会被 AMFI 直接 SIGKILL（实测退出码 9），因此也无法靠声明访问组来启用数据保护钥匙串。当前 Team 签名下也不使用该 entitlement。
  - 传统钥匙串条目按「应用标识 + 代码要求」记录 ACL；实测同一 App 跨 cdhash 重建（改代码重编后再读）仍可静默读写，无需重新授权。

### 端点

| 用途 | 端点 | 关键参数 |
|---|---|---|
| 连接验证 / 图片配置 | GET /3/configuration | — |
| 多类型搜索 | GET /3/search/multi | query, language, include_adult=false, page |
| 趋势 | GET /3/trending/{movie,tv,all}/{day,week} | language |
| 电影详情 | GET /3/movie/{id} | append_to_response=credits,images,similar,recommendations,external_ids,release_dates,watch/providers；include_image_language=zh,en,null |
| 剧集详情 | GET /3/tv/{id} | append_to_response=credits,images,similar,recommendations,external_ids,content_ratings,watch/providers |
| 季详情（分集） | GET /3/tv/{id}/season/{n} | language；每集返回 title、episode_number、air_date、overview、still_path、vote_average |
| 人物详情 | GET /3/person/{id} | append_to_response=combined_credits,images,external_ids |
| 系列详情（v1.19） | GET /3/collection/{id} | language；返回 name / overview / poster_path / backdrop_path / parts（电影列表，无 media_type） |
| 公司详情（v1.21） | GET /3/company/{id} | language；返回 name / description / headquarters / homepage / logo_path / origin_country / parent_company |
| 发现 | GET /3/discover/movie、GET /3/discover/tv | with_genres, primary_release_date.gte/lte（剧集用 first_air_date.*；排序同理：电影 `primary_release_date.*`、剧集 `first_air_date.*`）, vote_average.gte/.lte, vote_count.gte, with_watch_providers, watch_region, with_watch_monetization_types=flatrate\|free\|ads, with_runtime.lte（**仅电影端点有该参数**）, with_companies（v1.21 公司作品）, sort_by, page |
| 平台清单 | GET /3/watch/providers/movie、GET /3/watch/providers/tv | language, watch_region；返回该地区可用平台（`provider_id` / `provider_name` / `logo_path` / `display_priority`），缓存 30 天 |
| 类型列表 | GET /3/genre/movie/list、GET /3/genre/tv/list | language |

- 字段读取策略：评分用 `vote_average` + `vote_count`（少于 20 票标注「样本不足」）；时长电影 `runtime`、剧集 `number_of_seasons/episodes`；外链 IMDb 从 `external_ids.imdb_id` 拼 `https://www.imdb.com/title/…`。
- 制片公司（v1.21）：电影详情基础响应自带 `production_companies`（id / name / logo_path / origin_country），不需要额外 append；点公司再拉 `/3/company/{id}` 取简介与总部，其作品用 `discover/movie?with_companies={id}&sort_by=primary_release_date.desc` 获取。
- 发行信息（v1.20）：电影详情的 `release_dates.results` 按 `iso_3166_1` 分组，每条含 `release_date`（ISO 8601 时间戳，取前 10 位当日期）、`certification`（无分级为空串）、`type`（1 首映 / 2 点映 / 3 院线 / 4 数字 / 5 实体 / 6 电视，未知编号退化为「其它」）与 `note`；所有条目都无日期的地区整条过滤。
- DTO 全字段 optional + 自定义解码容错（未知枚举值兜底为 `.unknown`），TMDB 字段变化不导致解码失败。

### 图片

- 地址：`https://image.tmdb.org/t/p/{size}{file_path}`，尺寸按场景选择：

| 场景 | 尺寸 |
|---|---|
| 网格海报 | w342 |
| 详情左侧海报 | w500 |
| 详情 Hero 背景 | w1280 |
| 剧照 rail | w780 |
| 画廊大图 | w1280（与 Hero 同桶） |
| 人物头像 | w185 |

- **尺寸段不可省略**：URL 必须是 `base_url` + `w<尺寸>` + `file_path`；实测缺尺寸段（`…/t/p/{file_path}`）TMDB 一律返回 404 → 全站图片显示占位（踩坑记录，2026-10-17）。
- `PixelBucket` 桶 = `[185, 342, 500, 780, 1280]`（像素宽 = 展示宽度 pt × 2）；桶直接映射为尺寸段名 `w185 / w342 / w500 / w780 / w1280`。TMDB 没有 `w2000`，故上限取 `w1280`。
- 管线用到的 `base_url` 固定为 `https://image.tmdb.org/t/p/`（与 `/3/configuration` 的 `secure_base_url` 一致；配置缓存不可用时也能取图）。

### 网络代理

- 背景：国内直连 `api.themoviedb.org` 会被拦（实测 `curl` 8 秒超时），`image.tmdb.org` 通常可直连；而 `export https_proxy=…` 只影响 shell，从 Finder / 双击启动的 App 读不到环境变量，因此需要应用内代理设置。
- 设置页「网络」新增「代理」：`跟随系统`（默认，用系统网络设置里的代理）/ `手动`（`HTTP(S)` 或 `SOCKS5` + 主机 + 端口）。
- 实现：写入 `URLSessionConfiguration.connectionProxyDictionary`（HTTP/HTTPS/SOCKS5 三组键）；配置存 UserDefaults；网络层按「配置签名（模式|类型|主机|端口）」缓存 `URLSession`，签名变化即重建 —— 保存后下一次请求生效，无需重启。
- 首次启动若从未设置过代理，尝试从环境变量（`https_proxy` / `http_proxy` / `all_proxy`，形如 `http://127.0.0.1:7890`）预填一次 —— 从终端 / Xcode 启动时省一次手填；从 Finder 启动读不到，不影响默认「跟随系统」。
- 实测（2026-10-17，本机）：手动 `127.0.0.1:7890` 请求成功；指向无人监听的端口时本地监听器只收到 `CONNECT api.themoviedb.org:443` 后即失败 —— 证明代理字典确实生效；同一环境「跟随系统」直连 20 秒超时（被墙）。
- v1 不支持代理认证（用户名 / 密码）与 PAC 脚本；需要认证时请改用系统代理。
- 只影响本 App 的网络请求，不修改系统设置、不写日志。

### 节流、重试与错误

- 单 actor 串行节流（最小请求间隔 ~100ms）；搜索 300ms 防抖；翻页不预取超过下一页。
- 429：读 `Retry-After` 等待后重试一次；5xx / 超时：指数退避重试最多 2 次；仍失败归入错误态。
- 错误分类与 UX 动作：

| 错误 | 界面动作 |
|---|---|
| 未配置 Token | 全窗口引导页（去填 Token） |
| 401 Token 无效 | 引导页 + 「Token 可能已失效」 |
| 404 资源不存在 | 详情页内联提示 + 返回 |
| 429 被限流 | Toast「请求太频繁，稍后重试」 |
| 断网 / 超时 | 内联横幅 + 重试按钮 |
| 解码失败 | 「数据格式异常」+ 复制详情（日志） |

### 缓存（响应级）

| 数据 | TTL |
|---|---|
| configuration / genre list | 30 天 |
| 详情（含 append 数据、季详情） | 7 天 |
| 趋势 | 1 小时 |
| 搜索 | 10 分钟 |

- 缓存键 = 端点 + 参数 + language 的 SHA256；存储含写入时间戳；设置页可一键清除。
- 语言：请求统一带 `language=zh-CN`（可切 `en-US`）；zh-CN 自我介绍为空时，提供「查看原文简介」入口并标注来源语言。

### 数据流

```
View（SwiftUI）
   ↓ 事件
ViewModel（@Observable, @MainActor）
   ↓ async
TMDBClient（actor, 协议化）──→ 响应缓存（JSON, TTL）
   ↓ URLSession
image.tmdb.org ←── ImagePipeline（actor，独立二级缓存）
```

- 分页状态机：`idle → loadingFirst → loaded → loadingMore → loaded … → end / error(可重试)`；合并去重、末页判定独立成可测类型。
- 可测试性：`TMDBClientProtocol` + MockClient（预览 / 单测）、URLProtocol stub（集成测试）、SwiftData 内存容器（`isStoredInMemoryOnly: true`）；Core 层不 import SwiftUI，必要时抽本地 SPM 包供 iOS 复用。

## 6. 数据与持久化（SwiftData，纯本地）

采用 **SwiftData 本地容器**（不启用 CloudKit 同步：无付费开发者账号，数据仅存本机）；图片与 API 响应属于缓存，仍走文件，不进入数据库。

### SwiftData 模型

| 模型 | 关键字段 | 说明 |
|---|---|---|
| FavoriteItem | mediaType, tmdbID, title, originalTitle, year, posterPath, voteAverage, addedAt | 收藏 |
| WatchlistItem | 同上 | 观看清单 |
| HistoryEntry | 同上 + lastViewedAt | 最近查看，保留 500 条 |

- 去重键 = `(mediaType, tmdbID)`：写入前查询 + 合并（不依赖 #Unique 约束），保证同一作品只有一条。
- 从 V1 起使用版本化 Schema（`VersionedSchema` + `SchemaMigrationPlan`），为后续加字段（笔记、标签、个人评分）留好迁移路径。
- **Schema V2（v1.9）**：三类清单追加详情富化字段 `genreNames` / `runtime` / `director` / `topCast` / `countries` / `budget` / `revenue` / `detailFetchedAt`，全部可选，V1 → V2 走 `.lightweight` 迁移，无需搬运数据。
- **Schema V3（v1.13）**：再追加 `voteCount`（评分人数），供冷门指数使用；V2 → V3 同为 `.lightweight`，旧数据该字段为 nil，回填时补齐。
- **富化写入与回填**：详情页收藏 / 入清单时把已加载的详情顺手写入（不额外发请求）；旧条目在应用启动后由 `backfillDetails` 逐条补齐，单次上限 40 条。用 `DetailFetchResult` 区分「取到 / 已下线（404，记为已尝试）/ 网络失败（保留待补、立即中止）」，断网不会把条目误标为已富化。沙盒无后台定时执行能力，回填只在应用运行时进行。
- 模型保持「属性可选或带默认值」风格，以后如拿到账号需要云同步，可平滑加启 CloudKit，无需推倒重来。
- 容器损坏或迁移失败：备份并重建，不崩溃、不静默丢数据。
- **容器生命周期（实测踩坑）**：`ModelContext` 不会让 `ModelContainer` 存活；一旦容器被释放，后续 `fetch` 会在 SwiftData 内部直接 `brk`（SIGTRAP，无任何日志）。因此 `LibraryStore` / `HistoryStore` 一律持有容器（`init(container:)`），测试辅助方法也必须把容器与 Store 一起返回。

### 其余数据

- **Keychain**：TMDB Read Access Token（仅本机，不同步）；`service = app.latent.tmdb` / `account = read_token`，走传统登录钥匙串（原因与实测见第 4 节）。
- **UserDefaults（@AppStorage）**：语言、外观、代理配置、缓存上限等设置；最近搜索 10 条。
- `Caches/Latent/API/*.json`：响应缓存（含 TTL 元数据）。
- `Caches/Latent/Images/*`：图片磁盘缓存（LRU，默认上限 512MB）。
- 设置页显示各缓存占用（API / 图片）并支持分别清除。

### 生态集成路线

- v1：系统分享（ShareLink）、本地 SwiftData 数据层。
- v1.1：App Intents（Shortcuts：搜索作品、打开详情）、Spotlight 索引收藏与清单（本地能力；需要可验证 Team ID，免费 Apple Development 个人团队即可）。

## 7. 图片管线（核心自研点）

目标：在纯原生约束下达到 Nuke / Kingfisher 的常用能力——并发去重、取消、两级缓存、下采样、渐进淡入。

```
PosterImage(url, size)
  → ImagePipeline.image(for:) [actor]
      ├─ 内存缓存命中？→ 返回
      ├─ 磁盘缓存命中？→ ImageIO 下采样 → 返回
      ├─ in-flight 去重（同 URL 共享同一 Task）
      └─ 下载 → ImageIO 下采样 → 双写缓存 → 返回
  → 视图：骨架占位 → 150ms 淡入
```

- 内存缓存：`NSCache<NSString, NSImage>`，`countLimit = 400`、`totalCostLimit = 256MB`（按解码字节数计 cost）。
- 磁盘缓存：文件名 = `SHA256(file_path + size)`；超限时按最后访问时间清理最旧 20%（LRU）；缓存键含尺寸。
- 下采样：`CGImageSourceCreateThumbnailAtIndex`，`maxPixelSize = 展示像素 × 2`（Retina），避免全尺寸解码吃内存。
- 请求地址 = `base_url` + `w<尺寸段>` + `file_path`（桶 → 尺寸段映射见第 4 节；缓存键含尺寸段，缺段必 404）。
- 尺寸契约：`PosterImage` 自身不产生尺寸，完全由外部 `.frame(...)` 决定；图片画在 `Color.clear` 的 overlay 上并按其尺寸裁切。因此容器宽高比与图片不同（如方形头像里的 2:3 竖图）时只裁切、不溢出——早期用 ZStack 自撑尺寸会让竖图盖住下方的姓名/角色（踩坑记录，2026-10-17）。
- 取消：视图消失即 `task.cancel()`；取消不产生缓存写入。
- 失败：占位图（胶片图标纹理）+ 自动重试一次；仍失败静默保留占位，不弹错。
- 预取：网格向滚动方向预取下一屏首行（低优先级、容量很小）；Dispose 时取消。
- 内存警告：清空内存缓存（NSCache 自动 + 显式清理），磁盘不受影响。

## 8. UI / UX：极简 · 科技感 · 未来感

### 8.1 设计原则

1. **海报是唯一的大色块**：界面本色近中性，把色彩留给海报与剧照；UI 只保留一个强调色。
2. **未来感来自精度与秩序**：等宽数字、1px 细线、精确对齐、克制的层级；不靠霓虹渐变、玻璃拟态、粒子背景。
3. **原生优先**：traffic lights、系统工具栏、`.searchable`、原生菜单与表单；不做假标题栏，不自绘窗口控件。（实现说明：全局搜索用自定义 `SearchPanel` 浮层——需要分组结果与最近搜索的自定义渲染，`.searchable` 的候选列表无法胜任；其余仍走原生控件。）
4. **一屏一个主操作**：次要动作 hover 出现或收进右键菜单；破坏性操作不与主操作并排。
5. **逛比读重要**：80% 时间在网格里浏览——滚动顺畅、一屏尽量多张海报；详情是短暂聚焦，Push 进入、一键返回。
6. **渐进披露**：列表只给判断所需字段（标题 / 年份 / 评分）；完整元数据留给详情页。

### 8.5 动效

- 时长统一 120–220ms `easeOut`：hover 120、卡片上浮 140、图片淡入 150、Push 使用系统转场。
- 状态点呼吸 1.6s，仅在有网络活动时；骨架呼吸 1.2s。
- 呼吸类动效由 **Core Animation** 驱动（`BreathingFill`），**不要用 SwiftUI `Animation.repeatForever`**：macOS 27 实测无限动画会滞留在显示周期里，视图移除后仍逐帧重排，导致工具栏项被动画（设置齿轮"无限飞行"）与 CPU 空转（踩坑记录，2026-10-19）。
- 不用弹簧、视差、粒子、背景动画。
- 尊重「减少动态效果」：关闭呼吸、上浮改直切、淡入改立即显示。

### 8.6 页面细节

- **首次启动（无 Token）**：全窗口引导页——三步说明（申请 Token → 粘贴 → 验证）、一个输入框、一个主按钮、附 TMDB 官网申请链接；验证通过后进入主界面。
- **趋势页**：分段 `[今日|本周] × [电影|剧集]`，默认「今日 · 电影」；首屏骨架 10 张；滚动到底自动加载下一页。
- **列表页首屏状态互斥**（趋势 / 发现 / 搜索）：首屏失败时**只显示内联错误横幅 + 重试**，不与「空状态」同时出现；骨架（首屏加载中）、空状态（请求成功但零结果）、错误横幅（请求失败）三者互斥，按「错误 → 加载 → 内容 / 空」的优先级取一个。错误横幅仅在**列表中已有内容**（加载更多失败）时作为页脚出现。
- **搜索（工具栏全局）**：输入 → 300ms 防抖 → `/search/multi`；结果按「电影 / 剧集 / 人物」分组（前两者海报网格、人物为紧凑列表）；空查询显示最近搜索（可清空）；结果分页（面板底部「加载更多」）；`Cmd+F` 聚焦、`↑↓` 导航、回车打开、`Esc` 清空。
  - 拼音 / 首字母 / 英文查询（不含中日韩字符）时，先从本地收藏 + 观看清单取匹配项，在结果顶部显示「片库」紧凑行；本地组不依赖网络，TMDB 请求照常进行。中文查询不重复展示片库组。
  - 片库匹配规则见第 11 节：全拼、首字母、中英文标题、`ü → v/u` 双写；系统转写为主，多音字用 `Han-Latin` 与 `Han-Latin/Names` 两套读音合并，仍有个别词按系统默认读音。
  - 截图识别（v1.16）：输入框右侧取景框按钮或把图片拖进面板，用系统 **Vision** OCR（中英双语，`VNRecognizeTextRequest`）识别图中文字，逐行（最多 6 行）查 `/search/multi`，按「标题相似度 + 年份一致」打分排序；最高分 ≥ 0.9 且领先第二名 ≥ 0.12 就直接打开详情，否则在面板顶部列「识别结果」候选（最多 12 条，标注命中它的那行文字）由用户挑。识别 / 失败 / 候选三态互斥，失败以横幅提示不打断输入。
- 工具栏搜索框的实现约束：`ToolbarItem(placement: .principal)` 的 label **不能包含 `Spacer` 或弹性宽度**——macOS 27 会把整个工具栏项丢弃，搜索框完全不可见（踩坑记录，2026-10-19）。用定宽布局 + `overlay` 放右侧 ⌘F 提示。
- **电影 / 剧集详情**：Hero + 海报 + 标题区 + 操作（收藏 ☆、清单 ＋）+ 简介（折叠 / 展开）+ 在哪看（有数据时：在线看 / 租借 / 购买 + 地区菜单）+ 演职员 rail + 剧照 rail + 相似 / 推荐 rails + 右列事实栏；剧集在标题区下方显示**季选择器 + 分集列表**：每行 = 剧照缩略图 + 集号与标题 + 播出日期 · 时长 · 评分 + 简介（2 行省略，可展开；无简介显示「暂无简介」）。
- **剧集追更**（v1.18）：剧集详情的分集列表上方加一条「下一集」——集号与标题 + 人话日期（今天 / 明天 / N 天后 / 昨天 / 两周外给 M 月 d 日），日期是 accent 色；悬停显示完整播出日期。已完结 / 已取消的剧改为「已完结 · 共 N 季 M 集」的静态行；既无下一集也没完结信息时整条不出现。事实栏的「状态」由 TMDB 英文枚举翻成中文（连载中 / 已完结 / 已取消 / 制作中 / 计划中 / 试播），未知取值原样显示。
- **电影系列**（v1.19）：电影属于系列时，简介上方出现「系列 · 名称」横向海报条——标题右侧「共 N 部」+「整系列加入清单」（只补不在清单里的，全部已在时提示）。横条按上映日期正序，缺日期的排最后；卡片可点开、可右键，与其它海报任意位置一致。系列数据拉取失败或系列只有一部作品时整段隐藏，不占用版面。
- **发行信息**（v1.20）：电影详情在系列横条之后列「发行信息」——按地区折叠，默认展开中国大陆（无记录则第一个地区）；地区行显示地区名、分级（如 PG-13 / 12A）与最早上映日期，展开后逐条给「院线 / 数字 / 实体 / 首映 / 点映 / 电视 · 日期 · 备注」。排序为中国大陆 → 出品国 → 美 / 英 / 港 / 台 → 其余按地区名；先列 5 个地区，超出的折叠在「显示全部 N 个地区」。无发行记录的尾行地区整条过滤，不出现空行。
- **制作公司**（v1.21）：电影详情在发行信息之前列「制作公司」横向 chip 条——每个 chip = 公司 Logo（透明 PNG 用白底托住，无 Logo 用建筑图标）+ 名称，悬停给「查看 XXX 的作品」提示，点击进入**公司页**。
- **公司页**（v1.21）：左上公司 Logo（96×96，无 Logo 时建筑图标占位）+ 公司名 + 国家 / 地区 + 总部 / 母公司 / 官网（可点开）+ TMDB ID；下方「简介」，再下方「作品」按最新上映排序的网格，滚动到底继续加载。载入时先用电影详情带过来的公司名当标题，避免闪「载入中…」；公司信息拉取失败只显示错误横幅与重试，作品区不渲染。
- **图片画廊**（v1.22）：剧照 rail 的缩略图可点开大图画廊；标题右侧「全部 N 张」直接进画廊第一张；详情页主海报点击进入海报画廊（定位到当前海报）。画廊是 980×720 的 sheet：顶栏 = 作品名 + 「剧照 N / 海报 N」分段（两类都有时才出现）+ 计数 + 关闭（Esc）；中间大图按原比例适应、左右悬浮箭头翻页（首尾不循环）；下方一行说明「尺寸 · 语言」（TMDB 的 `iso_639_1` 为 null 时标「无文字」，两者都缺则不显示）；底部缩略图条高亮当前项并自动滚动居中，点击可跳转。翻页动画走 `UI.Motion.imageFade`，Reduce Motion 时直接切换。
- **人物页**：头像 + 简介 + 生卒 / 出生地 + 作品年表（原生 `Table`：年份 / 作品 / 角色 / 类型；可排序与筛选电影 / 剧集；点击进入详情）。
- **发现页**：筛选条（类型多选、年份区间、评分区间、观看地区 + 平台多选、排序）+ 网格；滚动到底自动加载下一页；筛选变化防抖 300ms 刷新（切换电影 / 剧集或地区时清空类型与平台选择并重新拉取）；一键重置。
  - 平台筛选（v1.14）：`/3/watch/providers` 按当前地区拉取可用平台，chip 显示 Logo + 名称；多选以 `|` 并集查询，固定的解锁方式为 `flatrate|free|ads`（可在线看）；界面保留「平台数据由 JustWatch 提供」来源说明。地区只在选了平台时参与请求，单独改地区不重发。
  - 快捷入口（v1.14）：标题栏「保存筛选」把当前类型 / 年份 / 评分 / 平台 / 地区 / 排序存成一条入口，默认名由条件摘要生成（如「科幻+冒险 · 2010–2024 · 评分 ≤7.0 · Netflix」），可改名；入口行点击即套用、× 删除；同名覆盖，上限 12 条。存 UserDefaults（JSON），不进数据库。
  - 一句话筛选（v1.15）：筛选条顶部一行输入框，回车或「解析」把句子填进下方筛选条并立即刷新，命中项以「已识别 科幻 · ≤90 分钟」回显；什么都没识别时给一句示例提示。解析完全在本地（`Core/Utilities/NLQueryParser.swift`），不联网、不依赖端上模型，断网可用且可单测。
    - 支持的说法：类型（TMDB 中文类型名 + 常见别名 / 英文名，如「科幻片」「搞笑」「sci-fi」）、年份（`2023 年` / `2020 年后` / `2019 年以前` / `90 年代` / `2020-2024` / `近年`）、评分（`8 分以上` / `评分 8` / `低于 6 分` / `高分`=7.5 / `烂片`=5.0）、时长（`90 分钟以内` / `两小时以内` / `一个半小时` / `短片`）、平台（已加载清单的名称或中文别名，如「网飞」「爱奇艺」）、排序（`票房` / `高分` / `最新的` / `经典老片` / `热门`）。
    - 取舍：**未在句子里出现的条件保持原值**，只覆盖提到的项；句子里点名了另一种作品类型（如「剧集」）时先切类型、重拉类型表与平台清单，再用新表重新解析；「分钟」不算「分」，`5 分钟以内` 不会被误判成评分上限；识别不出条件就什么都不改。
  - 时长上限（v1.15）：新增「时长」下拉（不限 / ≤90 / ≤100 / ≤120 / ≤150 / ≤180 分钟，仅电影显示），下发 `with_runtime.lte`。TMDB 只在电影端点提供该参数，剧集侧不下发也不显示。
- **收藏 / 观看清单页**：同款网格；排序（添加时间 / 评分 / 年份）；标题栏有筛选框、「片单卡」「选择」与导出；右键移除 / 移动清单；空态「还没有收藏」。
  - 筛选（v1.8）：标题栏紧凑输入框，支持中文标题、英文标题、拼音全拼与首字母（如 `liulangdiqiu` / `lldq`）；空格与标点忽略。筛选只影响当前网格 / 列表与「片单卡」快照；计数显示「命中 / 总数」。无命中时显示「没有找到…」与「清除筛选」。切换收藏 / 观看清单时清空筛选。
  - 多选（v1.7）：点「选择」进入多选；点按勾选 / 取消勾选，⇧-点按选择连续区间；未进入多选时 ⌘-点按可直接进入并勾选。选择键用 `(mediaType, tmdbID)`，电影 / 剧集同 ID 不串选。
  - 选择栏：显示「已选 N 部」，提供全选 / 取消全选、移到另一清单（收藏 ↔ 观看清单）、移出当前清单、完成；`Esc` 退出，`⌫` 移出当前清单。
  - 批量操作立即生效；按 `⌘Z` 或点内联「撤销」恢复。撤销会以原 `addedAt` 放回源清单；移动时只移除本次新增到目标清单的条目，原本已在目标清单的不动。
  - 单条（v1.7.1）：片库右键新增「移到观看清单 / 移到收藏」；单条移出 / 移动与批量共用同一份撤销记录。详情工具栏或海报星标触发的单条移出也会写入记录，回到片库页后可撤销。
  - 单条 / 批量操作后内联「已移出 / 已移到… + 撤销」8 秒后自动收起；撤销记录仍保留，片库页 `⌘Z` 与内联撤销共用同一份 `LibraryChange`，撤销后立即失效。
- **历史页**：按「今天 / 本周 / 更早」分组，行 = 小海报 40×60 + 标题 + 时间；可清除全部。
- **统计页（v1.9）**：全部由本地快照即时计算，不发网络请求。收藏与观看清单合并去重后展示：摘要（片库总数 / 电影 / 剧集 / 收藏 / 清单 / 电影总时长）、年代分布、评分直方图、最近 12 个月入库趋势（Swift Charts），以及类型 / 导演 / 主演 / 国家 Top 榜。未富化条目在对应维度自然缺席，页头提示「还有 N 条缺少详情」并提供「现在补齐」；空片库显示空态与前往趋势页入口。
- **设置页**：原生 `Form`——常规（语言、外观）/ 网络（Token SecureField + 验证 + 状态行 + 代理）/ 缓存（API 与图片占用 + 清除）/ 关于（版本、TMDB 署名、外链）。
- 「相似 / 推荐」/「剧照」rail 在详情数据到位后展示；无数据时整段隐藏，不留空标题。
- 返回按钮：只用 `NavigationStack` 自带的导航返回项，**不要**再自加 `.navigation` 工具项——两者会并排出现双箭头（踩坑记录，2026-10-17）；键盘 `⌘[` 走 `AppCommandBus.back`。
- **空 / 错状态**：断网与超时给内联横幅 + 重试；无结果给建议；404 在详情内提示并保返回。

### 8.7 菜单与快捷键

- `Cmd+F` 聚焦搜索；`Cmd+R` 刷新当前页；`Cmd+[` 返回。
- `Cmd+1` 趋势、`Cmd+2` 发现、`Cmd+3` 收藏、`Cmd+4` 观看清单、`Cmd+5` 历史、`Cmd+6` 统计。
- `Cmd+D` 收藏当前详情（Toggle）；`Cmd+Shift+D` 加入 / 移出观看清单。
- `Cmd+Shift+O` 从图片识别（文件菜单，打开搜索面板并弹出图片选择器）；也可以把图片直接拖到搜索面板。
- 网格 / 列表中：`↑↓` 移动焦点、回车打开、`Esc` 清空搜索或返回。
- 收藏 / 观看清单多选：⌘-点按进入并勾选、⇧-点按区间、`Esc` 完成、`⌫` 移出当前清单、`⌘Z` 撤销最近一次片库移出 / 移动（单条或批量）。
- 帮助菜单含「关于」与 TMDB 署名说明。

### 8.8 无障碍与反模式

- 对比度至少 AA；正文不小于 11pt；点击目标不小于 28×28。
- 状态不能只靠颜色：点 + 文字 / 图标；VoiceOver 读出海报为「标题，年份，评分」。
- 全键盘可达；图标按钮必须有 tooltip + accessibilityLabel。
- 不用纯黑 / 纯白铺底；不用霓虹渐变、满屏玻璃、粒子背景、发光文字。
- 不给列表行加大阴影 / 大圆角；不堆第二个强调色；不用 emoji 当图标。
- 不把主操作藏进菜单；破坏性操作不和主按钮并排。

### 8.9 系统集成与数据导出（v1.1）

**App Intents / Shortcuts**

- `搜索作品`：输入关键词（可选电影 / 剧集），调用 `/search/multi` 返回 `TitleEntity` 列表，可在 Shortcuts 里继续串联「打开作品」。
- `打开作品`：`OpenIntent`，参数为 `TitleEntity`；Spotlight 点击索引结果时由系统直接调用。
- `按 TMDB ID 打开`：参数为 TMDB ID + 电影 / 剧集，供蝉蜕等外部工具一键交接；打开的详情页走正常详情加载与历史记录。
- `在显影中搜索`：打开应用并把关键词预填进全局搜索面板。
- 所有 Intent 不新增网络权限、不写日志；Token 仍只从 Keychain 读取。App Shortcuts 提供「搜索作品」「在显影中搜索」两个免配置短语。
- **签名要求（2026-10-19 实测）**：macOS 27 的 `linkd` 只接受带 Team ID 的已验证 bundle。ad-hoc 签名（`CODE_SIGN_IDENTITY = "-"`）会导致 `OpenTitleIntent` 连接失败（`LNConnectionErrorDomain 1200 "AppleEvents communication failed."`；linkd 日志 `Unable to get teamId from app.latent.Latent`）。项目改用免费 Apple Development 个人团队（`project.yml` 的 `DEVELOPMENT_TEAM`），仍不需要付费账号；不要改回 ad-hoc。
- 导航经 `IntentRouter` 单例排队：应用未启动时先存 pending，`MainSplitView` 出现后消费；应用已启动时发通知即时消费。多个窗口共享同一目的地（自用场景可接受）。

**Spotlight**

- 索引范围：收藏 + 观看清单（去重；同时存在于两处时按收藏优先）。历史不索引，避免把「看过」误当成「收藏」。
- macOS 27 实测记录：直接使用 `CSSearchableItem` 写入的条目不出现在 Spotlight；改用 App Intents 的 `IndexedEntity` + `CSSearchableIndex.indexAppEntities` 后可见（Apple Developer Forums 835514）。因此 `TitleEntity` 同时承担 Shortcuts 参数与 Spotlight 索引单元，索引名为 `app.latent.library`。
- 索引构建：应用启动后、库变更后（收藏 / 清单增删、语言刷新）重建；先 `deleteAppEntities(ofType:)` 再批量写入，保证删除的条目及时消失。失败只写 os.Logger，不影响主流程。
- 点击 Spotlight 结果：系统匹配 `OpenTitleIntent`（`OpenIntent`），打开应用并 Push 对应详情。
- 索引属性：标题、年份 / 类型 / 评分描述、关键词（原名、类型标签、TMDB）；海报通过 `DisplayRepresentation.Image(url:)` 提供。

**导出**

- 入口：收藏 / 观看清单页与历史页的「导出」菜单；设置「数据」区与「文件」菜单可导出全部库。
- 格式：
  - **JSON**：`app` / `schemaVersion` / `exportedAt` / `language` + `favorites` / `watchlist` / `history` 四个数组；每条含 `tmdbID`、`mediaType`、`title`、`originalTitle`、`year`、`voteAverage`、`posterPath`、`posterURL`、`addedAt`（历史为 `viewedAt`）。日期 ISO 8601，便于蝉蜕或其它工具直接消费。
  - **Markdown**：按分区输出，每条含标题、年份、类型、评分、TMDB 链接；观看清单使用未勾选任务列表，收藏使用 ★ 标记，便于贴进 Obsidian / 笔记。
- 保存：`FileExporter`（`FileDocument` 包装 Data），默认文件名 `显影-<范围>-<yyyy-MM-dd>`；完全本地，不读取网络，不上传。
- 导出不包含 Token、代理配置、图片缓存与最近搜索。

### 8.10 分享卡（票据 / 片单）

把作品或影人的 TMDB 元数据排成一张**分享卡**，**用途是发朋友圈**（不模拟热敏打印、不做纸感拟真）。入口在**电影 / 剧集 / 人物详情页**工具栏，三者共用同一套卡面与渲染管线，差异只在字段与页脚的类型标注（2026-10-20 v1.3 落地）。多部作品的片单卡见本节末尾（v1.6）。

- 规格：3:4 竖版；画布 540×720pt，导出 **1080×1440**（@2x）。
- **版面预算（内容必须严丝合缝地落进 540×720，不允许溢出裁切）**：
  - 上下留白 **28pt**（放在最外层，所以顶部色带 / 报头双线 / 齿孔等装饰同样内缩，不会贴到画布边缘）；
  - 左右留白 44pt（色带横向通到画布两侧，属装饰而非内容）；
  - 海报块 **160×240pt**（2:3；账本 134×200，咖啡杯贴 150×150 圆形）；
  - 字段行**每行一行**（超长值缩字，不换行），行高 33pt；内容不足 720 时由弹性间隔吸收，页脚（标语 + 品牌行）始终贴底。
- 海报是主视觉；字段缺失**省略该行**，绝不伪造数值（没有预算就不印「预算」）。
- 字段随类型：电影「年份 / 上映 / 时长 / 类型 / 导演 / 主演」；剧集「首播 / 季数 / 集数 / 类型 / 主创 / 主演」；人物「生卒 / 出生地 / 领域 / 代表作（按人气取前三）」。三者字段行数上限一致（≤ 6），沿用同一版面预算。
- 不出现 TMDB 商标；页脚保留标语（tagline，缺则取简介前 60 字，仍缺则省略）；品牌行对剧集 / 人物额外标注类型（`显影 · 剧集 · 非商业分享`），电影保持 v1.2 的 `显影 · 本地元数据 · 非商业分享`。
- 导出动作：**复制到剪贴板**（PNG）/ **系统分享**（`ShareLink`，微信 / 备忘录 / AirDrop）/ **保存 PNG**（`FileExporter`）；预览就是同一张卡片按 0.6 缩放，所见即所得。

| 07 | 咖啡杯贴 | `#0C0C0E` | `#EAF8E6` | `#B8FF3D` | `#0C1406` → `#D6FF7A` |

**三层配色**

1. **固有调色板**：上表七款，纸底 / 墨色 / 强调 / 双色调写进代码即定稿。**默认走这一层**。
2. **保留封面原色（开关，默认关闭）**：海报不做双色调 / 灰度 / 反相处理，直接印 TMDB 封面原色（`ReceiptPosterMode.original`）。只影响海报，不动卡片配色。
3. **卡片配色取自封面（开关，默认关闭）**：从封面提取**主色 + 辅色**，**重算纸底 / 墨色 / 强调 / 双色调**（不再是只换色相）。为保证任何封面下文字都读得清，做了两条约束：
   - **纸底明度二选一**：封面整体偏亮（相对亮度 ≥ 0.32）取亮纸 `0.96`，否则取暗纸 `0.10`，避开采在中间灰；
   - **对比度保护**：墨色对纸底 ≥ 7:1、强调色对纸底 ≥ 4.5:1，不足则沿明度方向推到达标。
   - **提取方式**：封面降采样成 16×24 样本，按「色相 × 明度」分簇；主色 = 像素最多的色簇均值（整幅基调），辅色 = 与主色色相拉开、够鲜艳的色簇里平均鲜艳度最高者（占比 < 4% 的色簇忽略，避免噪点胜出）。单色封面退回主色的明度偏移；近灰（黑白片）封面**不加饱和**，避免中性色被凭空染红。

   两个开关默认关闭，是为了让七款锁定配色原样呈现（否则七款会共用同一套封面配色、失去各自的辨识度）；可单独开，也可同时开（原色海报 + 封面配色）。
   海报缺图时两个开关均禁用；封面取色失败退回固有调色板。

**片单卡（v1.6）**

把收藏 / 观看清单里的多部作品排成一张 3:4 的**片单卡**（如「我的年度十佳」），入口在**收藏 / 观看清单页标题栏**。它与单部作品的票据卡共用画布、调色板与导出管线，但版式是「多部海报网格」。

- 面板：左侧是 0.6 缩放的实时预览；右侧改片单标题（≤ 20 字）、勾选作品（1–12 部）、换七款风格、切换「保留封面原色」。默认预选**当前列表排序的前 12 部**；卡片顺序跟随列表当前排序，不支持拖拽重排。
- 数据：打开面板时取列表快照，只映射标题 / 年份 / 海报；不请求详情，不伪造缺失字段。标题留空时回退「我的片单」。
- 快照传递（v1.6.1）：点按「片单卡」时把 `kind` 与列表快照作为 `Identifiable` 负载随 sheet 一起传入（`.sheet(item:)`），不依赖另一个先写入的 `@State`；面板出现时再按快照校准预选。列表为空时显示「先去收藏几部」空态，而不是误报「已全选」。
- 版面：画布同为 540×720pt / 导出 1080×1440；顶部 5pt 强调色条 + `LATENT / PLAYLIST` 品牌行 + 可编辑标题 + 「来源 · N 部」副标题；底部 `显影 · 片单 · 非商业分享` 品牌行。
- 网格（按选中数量自适应，最后一排居中）：
  - **1 部**：单列 250×375pt；
  - **2–4 部**：2 列 168×252pt；
  - **5–9 部**：3 列 114×171pt；
  - **10–12 部**：4 列 104×156pt。
  - 海报统一 2:3 圆角矩形，左上角印 `01`–`12` 序号，底部渐变上压片名（最多两行）与年份。
- 配色：沿用七款锁定调色板与海报处理（双色调 / 灰度 / 反相）；「保留封面原色」对全部海报生效。**不提供「卡片配色取自封面」**——多张封面无法确定唯一主色，只有单主体票据卡保留该开关。
- 缺海报：用当前风格的双色调渐变占位，不伪造封面；分享图在标题 / 选片 / 风格变化后重算（250ms 防抖，避免逐字输入时反复离屏渲染）。
- 动作：复制到剪贴板 / 系统分享（`ShareLink`）/ 保存 PNG（`FileExporter`）；预览、分享、保存使用同一张卡。
- 边界：片单卡复用七款调色板与海报处理，但**不套**票据卡的齿孔 / 片孔 / 圆章等单主体装饰；网格版式优先。

**边界**

- 分享卡是**独立 artifact**：配色不受 8.1「海报是唯一大色块 / 界面只保留一个强调色」约束——它是产出物，不是应用界面。
- 海报处理随风格：双色调（多数）/ 灰度（铅字报头）/ 反相（暗房底片）/ 圆形裁切（咖啡杯贴）；开启「保留封面原色」后统一切换为原色。
- 热敏款的中文用系统字体（PingFang SC）保证可读，点阵感靠字距与字重实现，**不内嵌字体**。
- 实现位置：`Features/Receipt/`（票据卡）与 `Features/Playlist/`（片单卡）；渲染依赖 SwiftUI `ImageRenderer`；按第 5 节「Core 层不 import SwiftUI」的约定，不放 Core。

### 布局验证（离屏渲染）

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 用户没有 Token | 无法使用 | 引导页给出三步申请说明 + 官网链接；不内置公共 Key |
| TMDB 字段变动 | 解码失败 | DTO 全 optional + 未知枚举兜底 + fixture 定期更新 |
| zh-CN 数据不全 | 简介为空 | 回退原文并标注来源语言；提供「查看原文」 |
| 图片磁盘膨胀 | 占空间 | LRU + 上限 512MB + 设置页显示占用与一键清除 |
| 429 限流 | 请求失败 | 客户端节流 + 防抖 + Retry-After 退避 |
| 商标 / 条款合规 | 被要求整改 | 应用名不含 TMDB；关于页署名；缓存与频率守约 |
| Swift 6 并发 | 编译 / 运行问题 | actor / `@MainActor` 分层；DTO 全 Sendable |
| 无付费开发者账号 | 无法公证 / 上架，CloudKit 与 iCloud 能力不可用 | 按自用定位（本地构建运行）；功能零依赖 iCloud；将来需要时再补账号 |
| SwiftData Schema 迁移 | 数据结构变化出错 | 从 V1 起版本化 Schema + MigrationPlan；内存容器覆盖迁移测试 |
| 大网格内存 | 卡顿 / 崩溃 | LazyVGrid + 下采样 + 缓存上限 + 预取小步滑 |
| 只读客户端的功能天花板 | 用户想「标记已看」 | 本地清单承载（收藏 / 观看清单 / 历史），不回写 TMDB |

### 14.6 输入与本地智能

- **自然语言搜索**：**v1.15 已实现（规则解析版）**——发现页输入「90 分钟以内的科幻片」这类句子，解析成类型 / 年份 / 评分 / 时长 / 平台 / 排序并填进筛选条。实现为纯本地规则引擎（`Core/Utilities/NLQueryParser.swift`），不依赖端上模型，断网可用、可单测。端上模型版本（理解更口语化的说法、支持偏好式描述）仍留在 backlog，前置见下条。
- **快捷指令 + Siri**：对 Siri 说「显影，找一部适合今晚的片」，本地解析 → 筛选 → 出结果（扩展已有 App Intents）。
- **拼音搜索**：**v1.8 已实现**——`CFStringTransform` 的 `Han-Latin` / `Han-Latin/Names` 两套转写合并，去音调后生成全拼与首字母；`ü` 同时接受 `v` / `u`；作用于片库筛选与全局搜索的「片库」组。纯系统框架、0 依赖。多音字由系统两套转写取并集（长 / 曾 / 解 / 单 等）加一份精简读音表（地 / 了 / 行 / 乐 / 重 等）覆盖，仍有个别词只给单一读音，必要时可用中文标题搜索。
- **Live Text 截图识别**：**v1.16 已实现（片名 + 年份版）**——拖入海报 / 剧照截图或按 `⌘⇧O` 选图，Vision OCR（中英）识别文字后逐行反查 TMDB，按标题相似度 + 年份一致打分：明显胜出直接打开详情，否则列候选。演职员抽取（从截图里认出演员名再反查）仍留在 backlog。
- **Foundation Models（Apple Intelligence）（前置，实测不满足）**：端上模型做自然语言解析与摘要。`SystemLanguageModel.default.availability` 在**本开发机（M1 Pro，macOS 27）实测返回 `deviceNotEligible`**，即该机不支持 Apple Intelligence（此前文档误写为「满足」）；`LanguageModelSession` 冒烟测试同样失败。因此 v1.15 的自然语言筛选走本地规则引擎，端上模型版本需换支持 Apple Intelligence 的机器才能验证与验收。
- **多模态海报理解（存疑）**：让端上模型直接「看」海报理解其内容。与 Live Text 同源，成本高、收益不确定，优先级低于 Live Text。
- **Force Touch 压力感应（存疑）**：macOS 对第三方分级压力 API 的支持有限，且多数触控板不区分层级，需先验证可行性。

- **深链** `latent://movie/603`：已有「按 TMDB ID 打开」的 Shortcut，加 URL scheme 更顺手。
- **右键复制扩展**：复制「片名 + 年份」、Markdown 简介、直达链接。
- **Letterboxd / Trakt CSV 导入**：快速填充片库。注：iCloud / CloudKit 是红线，但「文件导入 / 导出」做手动同步不违反约束。

### 14.8 界面细节

- **「显影」加载动效**：把「加载」做成「显影」——内容从无到有、缓缓浮现。须守 8.5 节：120–220ms easeOut、无弹簧 / 粒子、Reduce Motion 全降级。
- **「潜影」占位**：图片未加载时不用灰块 / 胶片图标，改用极低对比度的「潜影」纹理，比现在更含蓄。契合「潜影」这个命名本意。

### 14.9 工程重构（不改变产品）

- **MetadataKit**：把 `TMDBClient` + `ImagePipeline` + 分页状态机 + SwiftData 模型抽成**本地 SPM 包**，Provider 协议化——仍是自有代码，**0 第三方依赖**不变。与蝉蜕同源（见文末备注），两边长期并用时可共用一套实现。

### 14.10 超出当前产品定位（需单独立项）

- **多数据源扩展（超范围）**：书（Open Library / 豆瓣读书）、音乐（MusicBrainz / Discogs）、游戏（IGDB）、动漫（Bangumi）、播客（Podcast Index）、展览 / 演出（本地手动录入）。这等于把「TMDB 元数据浏览器」重定义为「多源文化档案浏览器」，属**产品再定义**，不能作为当前 backlog 直接排期；`MetadataKit` 的 Provider 抽象（14.9）是它唯一的技术前提。

### 14.11 明确不做

媒体播放（正片 / 预告片，GIF / Live Photo 属「产出物生成」不在此列）、账号 / 云同步 / CloudKit、社交功能（用户发评论、动态）、评分 / 评论回写 TMDB（只读客户端）、第三方依赖、自建后端、本地视频文件与 TMDB 自动匹配（蝉蜕职责）——见第 1 节非目标。

**年度回顾（Year in Review）**：不做——本地历史只记录「打开过」，无法区分看完 / 弃剧；收藏与观看清单也没有观看日期，按自然年统计会误导。片单卡已覆盖「年度十佳」这类分享需求（见第 8.10 节）。
